## Defects seen (fixed after this campaign, in the commit that follows)

- **The landing gate stopped on a flaky test (4 rounds in full-11, 1 in full-10).**
  `tests/test_ids.py::test_ids_are_unique_within_a_workbook` failed in the whole-suite gate. It passed on the
  base, so the gate sent the bead back to implement, although the check loop had already excused it as flaky.
  Fix: before holding the gate, a test that passes on the base, in a file the bead did not change, is rerun on
  the final tree. A pass there is flaky, gets filed as a bug, and lets the gate through.
- **A context-role guess became a human question (full-11/toy-8, rows).** The context role (composer) listed
  the risk "anchored $ rows must not [move on INSERTROW]", which is wrong for a spreadsheet. refine took it as
  "bead design notes" and declined to add a criterion. Its assumptions ended with "needs a decision, the user
  should confirm". Every criterion was met, but the judge then answered `human`. The bead was parked, and
  undo (toy-9) stayed blocked behind it. Fixes:
  - refine: an assumption is a choice made, never a question left to the user. The repository context is
    another agent's quick read, not a requirement.
  - judge: an open question about behaviour no criterion names is not a reason for `human` when every
    criterion is met.
- **Red perf tests ran without a bound (full-12/toy-14).** The tests role wrote time-limit tests for 10k–50k
  cells and ran them against the O(n²) code. composer, the haiku fallback and its resume each hit the 20-minute
  role limit, and the bead was parked as `tests-role-failed`. Fix: the tests prompt requires a time-limit test
  to stop itself with a timeout a little above the limit.
